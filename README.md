# master-sae-experiments

Code and results for the master's thesis **Improving LLM Performance via Sparse Autoencoder Feature Steering** (TU Berlin). The method is a five-phase training-free pipeline that leads from a frozen LLM, a public SAE, and a labelled benchmark to a single measured intervention. Every candidate feature is validated by moving it alone, and the questions that build the intervention are never the ones that judge it.

## Important folders and files

```
configs/                   three YAML layers that define: models, SAEs, benchmarks
src/sae_experiments/       the pipeline
run_experiments_final.py   batch experiment runner
results/                   one folder per run with result JSON, cache, plot, log
dashboard.py               Streamlit viewer over results/
```

## `configs/`

| Subfolders | Files | Holds |
|:--|--:|:--|
| `configs/models/` | 30 | Hugging Face model id, `d_model`, `n_layers` |
| `configs/saes/` | 80 | `architecture` (`relu`, `batchtopk`, `jump_relu`), `repo` and `filename` pattern, `d_hidden` width, `hook_point` site, `available_layers`, and `model` |
| `configs/benchmarks/` | 20 | dataset id and splits, answer-key type, field mapping, prompt instruction |

Because an SAE config names its own model, three arguments fully specify a run, and a fourth adds the transfer benchmarks:

```bash
uv run sae-experiments \
  --sae configs/saes/eleutherai_llama32_1b_131k_mlp.yaml --layer 7 \
  --benchmark configs/benchmarks/commonsenseqa.yaml \
  --generalisation configs/benchmarks/arc_challenge.yaml \
                   configs/benchmarks/hellaswag.yaml \
                   configs/benchmarks/openbookqa.yaml
```
## `src/sae_experiments/` — the pipeline

One experiment is one `Pipeline` object (`pipeline.py`) running the five phases of the thesis's methodology chapter.

| Phase | Where |
|:--|:--|
| **0 · Difficulty screening** | `screening.py`, `splitting.py` |
| **1 · Feature discovery** | `features.py` |
| **2 · Causal validation** | `phases.py` |
| **3 · Configuration search** | `phases.py`, `intervention.py` |
| **4 · Holdout evaluation** | `reporting.py`, `kfold.py`, `plotting.py` |
| **Cross-benchmark generalisation** | `generalisation.py` |

## `run_experiments_final.py` — the batch runner

`EXPERIMENTS` holds 220 `Experiment(...)` entries, one per (SAE, layer, benchmark) cell, all at batch size 1. The benchmark is one of the two primary ones, CommonsenseQA or ARC-Challenge, and every cell is transferred to the other of the two plus OpenBookQA and HellaSwag. Each entry runs as its own `python -m sae_experiments` subprocess and writes into `results/EXP-N/`, screening cache included, so no state is shared between cells.

```bash
uv run python run_experiments_final.py --dry-run      # print the queue and the exact commands
uv run python run_experiments_final.py --only 56      # one cell: queue position N is EXP-(299+N)
uv run python run_experiments_final.py --worker 1/4   # shard the queue across four GPUs
uv run python run_experiments_final.py --git-push     # commit and push new result folders
```

## `results/` — one folder per run

A completed cell leaves four files behind, here `EXP-355`, the reference experiment the thesis walks end to end:

```
results/EXP-355/
├── commonsenseqa_batchtopk_L7_K32_20260725_071503.json   the run's full record
├── logit_screening_commonsenseqa_llama32_1b.json         Phase 0 scores per question
├── full_reporting_commonsenseqa_batchtopk_L7_K32.png     the reporting plot
└── 20260725_011828_EXP-355.log                           everything the run printed
```

`final_matrix_summary.md` and `final_matrix_summary.jsonl`, beside the folders, carry the cells in one table, regenerated by `scripts/summarize_final_matrix.py`. The `EXP-300`+ folders are the final matrix. The lower numbers are earlier exploratory rounds that the reported study does not draw on.

## `dashboard.py` — browsing runs locally

```bash
uv run --group dashboard streamlit run dashboard.py
```

It reads `results/` and has four pages: **Overview** (all runs, filterable), **Detail** (one run in full), **Log** (searchable log), and **Charts** (layer, model, top-k and site comparisons, plus a generalisation heatmap).

## Experiment index

**Columns.** `Site` is where the SAE reads (`resid_post` after the block, `mlp_out` the MLP output) and `Width` its dictionary size · `Holdout` and `Base` are the holdout questions and the baseline accuracy on them · `Surv.` gives the features that survived Phase 2 against those tested · `Rank`, `k+/k-` and `α` are the configuration Phase 3 chose: ranking by causal effect or by frequency difference, features amplified and suppressed, strength · `Sel.` and `Gain` are accuracy changes in percentage points on the selection subset and on the holdout · `Flips` counts holdout answers corrected and broken · `p` is the one-sided binomial on those flips · `Other`, `OBQA` and `HS` are transfer to the other primary benchmark, OpenBookQA and HellaSwag.
